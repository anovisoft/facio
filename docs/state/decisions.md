## Две цели, один клин

Успех — если выстрелит хотя бы одно:

1. **iOS / TestFlight** — клин живёт на людях, цель порядка ста тестовых.
2. **Витрина Upwork** — тот же клин выглядит как вышедшее приложение, а не как макет.

Минимального прототипа (зашитый посев, без рта, «чат потом») для витрины мало. Полного каталога, сковородки и синка для обеих целей тоже нет. Нужен **законченный вертикальный кусок**: founding journey на нативной крышке, с ртом, напоминанием и срывом.

Впечатление = крышка как настоящее iOS-приложение + вывод сел в механику на записи. Не число экранов.

1. Бренд-зелень из Expo как `.tint`.

Замки: системные цвета; стекло на плитках и контролах Use; фон с пятнами; системный back; `.plain` на полях. Тема следует системе — атмосфера не может быть светлой при dark. Новый полир — только по списку PO, не «улучшить всё».

## Стек

- Телефон: **SwiftUI**, новое приложение. Expo / RN не продолжаем.
- Закон и золотые тесты: Python (`packages/domain`). Фикстуры основателя гоняет и клиент.
- Сервис: FastAPI в `apps/api`. Сейчас — клин (ход рта, ключ на сервере). Волны В1–В3 **собирают полноценный сервис** в том же пакете: роутеры, провайдеры, MCP, затем Apple + Postgres + jobs. Типовой шаблон `fastapi-templates` — не в В1–В2; **в В3 можно** (БД, аккаунт, стол). Вендор модели — из `FACIO_MODEL_NAME`. Локально — Compose; Postgres только в В3, не из `archive/docker-compose.yml`.
- Данные до шага 6: SQLite на устройстве. Крышка читает локальный склад (P5).
- Контракт: JSON Schema из питоновских моделей. Swift — тонкий порт тех же фикстур, не второй закон из головы.
- Деплой клиента: iOS 18+, портрет, не планшет. **Liquid Glass включён** (PO, 2026-08-16): плитки и контролы Use, fallback — materials. `GlassEffectContainer` — только кучка кнопок Use, не пак крышки. Акцент — системный, не «лесной» зелёный из Expo. Тема — system light/dark, атмосфера и launch одного scheme. Use отдаёт системный back, чтобы жил свайп от края.

Не тащить в В1–В2: векторный поиск, Postgres «на вырост», брокер, RAG-корпус спорта, шаблон `fastapi-templates`. В В3: Postgres, `search_facts` по своим фактам, и **можно** `fastapi-templates` для сессии БД и репозиториев.

## Инварианты, которые нельзя нарушить в коде

1. Открыть крышку, тикнуть, посчитать срыв, выбрать час напоминания — без модели.
2. Каталог виджетов закрытый. Модель заполняет схему; клиент рисует и гоняет.
3. Подсказка без места показа не пишется.
4. Исправление по умолчанию — в момент дела. Пояснение — за `?`.
5. Срыв — арифметика. Модель может сформулировать одну утреннюю фразу, не решает, есть ли карточка.
6. Ответ на срыв — уменьшить или убрать, никогда «постарайся».
7. Пустой сегодня без обещания — можно. Пустой сегодня при отставании от ритма — нельзя молчать.
8. Делать и смотреть — разные экраны. Свайп в другой день посреди подхода запрещён.
8a. Готовый случай **сегодня** остаётся в том же Сегодня, внизу, тусклый. Не Lifetime. На следующие сутки снимается сам.
9. Вывод, который остался только текстом — баг.
10. Боль — граница. Нельзя поднять цель или ритм через «больно».
11. Прогресс подхода нельзя затирать поздней правкой структуры (когда появится синк — два канала).
12. Не добывать библиотеку картинок и каталог упражнений.
13. Do-time на языке человека, короткая команда. Лекцию нельзя класть поверх «держи корпус».

## Рот

Для витрины и для чужого человека рот — часть клина, не шаг «потом».

- На крышке внизу всегда поле. Тап → чат почти на весь экран. Свернуть = спрятать текущий тред, не начать новый.
- «Новый чат» — справа сверху листа.
- PO: рот есть и на Use (расходится с RFC «на Use чата нет»). Слушаем PO.
- Патч проверяется схемой. Боль в питоне режет рост цели/ритма.
- Eval золотых реплик — до расширения набора инструментов (вопрос 22).
