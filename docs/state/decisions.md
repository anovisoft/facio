# Зафиксированные выводы

Инженерные решения после разбора RFC (2026-08-15).  
Продуктовые замки v0.7 не повторяем — они в [07](../rfc/07-open-questions.md) сверху файла.

---

## Центр системы

Три вещи живут в одном объекте, иначе это чужое приложение:

| Кусок | Один он уже есть у |
|-------|-------------------|
| Причина («держи корпус») | заметки, чужой чат |
| Ритм (три раза в неделю) | привычки |
| Срыв (три недели тишины) | никто честно |

Практика — центр модели: ритм, окно времени, подсказки, расчётный срыв.  
Виджет — исполняемая поверхность одного случая.  
Крышка — проекция «что пора сейчас», не вторая инвентаризация.

Живое состояние не восстанавливается из переписки. Карточка в чате — снимок, не рантайм.

## Стек

- Телефон: новое приложение на Expo / React Native. Архивный клиент не продолжаем.
- Закон и тесты: Python (модели + расчёт ритма, срыва, крышки, времени напоминания).
- Сервис HTTP: FastAPI — **не с первого дня**. Появляется вместе с узким разговором или синком, не раньше.
- Данные первых недель: только устройство. Сервер записи — поздний шаг.
- Общий контракт: JSON-схема из питоновских моделей → типы на клиенте. Два языка сходятся на фикстурах, не на «локальном сервере в телефоне».

Питон в первые дни — закон и проверки, не обязательно запущенный сервис.

## Что брать из архива, что хоронить

**Копировать куски, не импортировать монолит:**

- рантаймы счётчика, галочки, таймера, степпера;
- тема, языки, стекло, локальное хранилище, выкладка на телефон;
- локальные уведомления;
- обёртка модели: структурированный ответ, повтор при плохой схеме, сырой ответ в журнал.

**Не тащить:**

- гайд / продолжить / сессия / путь / лента планов / обложка / цикл;
- проект + действие как онтологию;
- конвейер «намерение → путь»;
- идентификатор устройства как долгий вход;
- библиотеку чертежей, векторный поиск, биллинг тренера.

Старый стек оптимизировал конечный путь. Новый — практику, которая сама возвращается. Чинить схему дороже, чем начать каркас заново.

## Инварианты, которые нельзя нарушить в коде

1. Открыть крышку, тикнуть, запустить таймер, посчитать срыв, выбрать час напоминания — без модели.
2. Каталог виджетов закрытый. Модель заполняет схему; клиент рисует и гоняет. Новый тип — решение продукта, не генерация.
3. Подсказка без места показа не пишется. Нет места — это заметка, заметки уже провалились.
4. Исправление по умолчанию показывается в момент дела. Пояснение — по запросу за знаком вопроса. Иначе первый повтор тонет в тексте.
5. Срыв — арифметика: обещанный ритм против сделанных случаев. Модель может сформулировать одну утреннюю фразу, не решает, есть ли карточка.
6. Ответ на срыв — уменьшить или убрать, никогда «постарайся».
7. Пустой сегодня, потому что ничего не обещано — можно. Пустой сегодня, потому что практика отстала от своего ритма — нельзя молчать.
8. Делать сейчас и листать прошлые разы — разные экраны. Свайп в другой день посреди подхода запрещён.
9. Вывод из разговора, который остался только текстом — баг. Он должен стать подсказкой, ритмом, окном или целью.
10. Боль — граница. Общая техника и меньшее число. Нельзя поднять цель или ритм через «больно».
11. Прогресс подхода (галочки, текущее число, прошедшее время, шаг степпера) нельзя затирать поздней правкой структуры. Два канала записи, когда появится синк.
12. Не добывать библиотеку картинок и каталог упражнений. На подсказке — одна ссылка (обычно видео в шаге) или своё фото.

## Разговор: три толщины

Это главный вывод сессии про «а как тогда править план».

| Толщина | Что умеет | Когда |
|---------|-----------|--------|
| Палец | переписать подсказку, сменить цель, уменьшить ритм | автор, первые дни, обязательно даже если разговор будет завтра |
| Узкий разговор | одно поле про выбранную практику → только безопасный патч: добавить подсказку / сменить цель / сменить ритм / уменьшить | второй человек или автор хочет править словами с первой недели |
| Полный чат | новый тред, снимки по центру, прыжок из меню плитки в главу | после того как подсказка и срыв уже живут на крышке |

Полный чат ≠ единственный способ уточнить план.  
Питон-сервис ≠ единственный способ вызвать модель. Узкий разговор можно ударить из телефона; общий проверяльщик схемы и журнал — причина поднять сервис позже.

Узкий разговор не открывает новый тред, не рисует снимки и не тащит сковородку. Одно поле, живая плитка, одна строка подтверждения.

## Две недели без сервиса

Это не две недели без правки плана.

- Автор уже знает метод. Ему проверить: вернулась ли причина в момент подхода, всплыл ли срыв до провала. Подсказку можно вписать руками.
- Второй человек (зал, не поняла формулировку) без модели не входит: её план снова умрёт в чужом чате. Ей нужен узкий разговор сразу, не полный мессенджер.

Критерии остановки из RFC (писать до старта, не после):

- за две недели ни одна подсказка не была прочитана в момент дела, когда это было важно — механика не работает;
- срыв ни разу не всплыл до того, как провал уже случился — то же.

Если сработало на авторе и родственнике — это право искать чужого человека, не право строить сервер.

## Двое суток кода

Можно собрать **клин, который касается нужных поверхностей**.  
Нельзя честно закрыть все семь шагов плана.

Влезает: закон, крышка, два предмета из заготовки, подсказка на счётчике, галочка, одно напоминание, карточка срыва, правка пальцем, узкое поле в модель.

Не влезает: чат как у ЧатГПТ, жесты крышка/сковородка без сюрпризов, карусель прошлых раз, настоящий вход и синк, цена за активный день.

Опасность не в плохом коде за выходные. Опасность в том, что чат и «сервер» будут казаться готовыми, и следующая неделя уйдёт в полировку переписки.

Старый проект уже так делали: за дни вставали путь, гайд, лента — центр оказался не тот. Скорость не лечит неверный объект.

## Открытое, не выдумывать в коде

Пока стоит консервативная колонка [07](../rfc/07-open-questions.md):

- поставщик входа — не выбирать, пока нет синка на несколько устройств;
- синк целиком не спроектирован: два канала (структура / прогресс), не одна перезапись всего виджета;
- цена за активный день — измерить, не выдумать сумму;
- открытая практика («построить проект») — считать, что не работает, пока живое использование не скажет иначе; случай = следующий конкретный шаг, не карта на месяцы;
- готовую глубину готовки и богатый степпер не начинать, пока держатся несколько мелких практик.

## Язык в этой папке

Документы состояния — по-русски, чтобы не держать две головы.  
Имена в коде могут быть английскими и обязаны совпадать с RFC: `Subject`, `Cue`, `Widget`, `Instance`, `surface`, `cadence`, `drift`. В разговоре с человеком — крышка, сковородка, практика, подсказка, срыв.
