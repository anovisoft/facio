# Things we should NEVER do

Hard constraints. Violations require explicit founder-level exception.

## Product

1. **Never** make unbounded general chat the primary surface.
2. **Never** lock deterministic next actions of an active project behind a paywall.
3. **Never** use guilt/shame dark patterns as core retention.
4. **Never** claim medical diagnosis, treatment, or guaranteed health outcomes.
5. **Never** target eating-disorder weight loss behaviors; detect and deflect.
6. **Never** ship “any goal supported” marketing while coverage is wedge-thin.
7. **Never** auto-start multiplayer social without consent and product maturity.
8. **Never** delete user project history without a clear user-initiated path + recovery window.

## AI / data

1. **Never** apply unvalidated LLM plan text directly to the scheduler.
2. **Never** train public models on private user media/evidence without explicit legal basis and product need (default: don’t).
3. **Never** index raw PII-laden intentions into cross-user retrieval corpora.
4. **Never** let Coach bypass safety policy tools.
5. **Never** run silent full-plan rewrites without a user-visible diff.
6. **Never** optimize for tokens-of-engagement.

## Taxonomy / content

1. **Never** auto-publish LLM-generated blueprints to production without human review + tests.
2. **Never** create unbounded OutcomeType explosion for synonyms.
3. **Never** retrieve sensitive blueprints solely by embedding similarity.

## Business

1. **Never** sell user intention data.
2. **Never** pretend to be a licensed financial advisor / clinician without being one.
3. **Never** build growth loops that require users to spam friends to continue their plan.

## Engineering

1. **Never** make online LLM required for reading today’s action.
2. **Never** skip eval harnesses when expanding generative surface area.
3. **Never** store secrets in blueprints/content repos.

If a stakeholder says “just this once” about the above, write an exception RFC with expiry date — or refuse.
