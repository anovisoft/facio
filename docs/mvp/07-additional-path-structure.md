# 07 — Additional: структура Path

Дополнение к `02-scope.md` и `03-ux-flows.md`.  
Фиксирует **три уровня структуры пути** для MVP. Это не свободный UI-конструктор: клиент рендерит известные типы, LLM заполняет schema.

---

## 1. Плоский список шагов Path (база, must)

Path = упорядоченный список шагов (`actions[]`).

Каждый шаг:

```text
id
title
why                 # required — «Почему сейчас»
detail              # how-to / инструкции (критично для готовки)
estimate_min
day_offset | due_at
sort
status              # pending | done | skipped
group_id?           # см. §2
checklist_items[]?  # см. §3
```

**Home «Сегодня»** показывает ровно один текущий шаг (по правилам очереди), не весь список.

**«Весь путь»** — полный ordered list (с группировкой, если есть §2).

Без этого уровня MVP не существует.

---

## 2. Группы / секции в Path (must)

Шаги могут входить в секции, например:

- Покупки  
- Подготовка  
- Готовка  
- Тренировки · Неделя 1  

### Модель

```text
groups[] | stages[]
  id
  title
  sort

actions[]
  group_id → groups.id
```

Альтернатива без отдельного массива: `group_title` + `group_sort` на каждом action (хуже для rename, ок для MVP если проще).

### UX

- В **«Весь путь»**: секции как заголовки, под ними шаги.  
- В **«Сегодня»**: один шаг; над ним можно мелко показать имя секции («Покупки»).  
- Порядок: сначала по `group.sort`, внутри — `action.sort`.  
- Секция без шагов не показывается.

### Зачем

Карбонара и длинные цели иначе выглядят как свалка из 15 пунктов. Секции дают карту без отдельного «конструктора экранов».

---

## 3. Чеклист внутри шага (must где уместно)

Внутри одного шага — подпункты, которые отмечаются отдельно.

Пример шага **«Купить продукты»**:

```text
☐ яйца
☐ гуанчиале
☐ пекорино / пармезан
☐ спагетти
```

### Модель

```text
checklist_items[]
  id
  title
  done: boolean
  sort
```

Пустой `checklist_items` = шаг без чеклиста (обычный «Сделано» одним тапом).

### UX / правила завершения шага

| Ситуация | Поведение |
|----------|-----------|
| Нет чеклиста | **Сделано** закрывает шаг |
| Есть чеклист | Можно отмечать пункты по одному; **Сделано** по шагу — когда все пункты done **или** явное «Сделано» с подтверждением «остались неотмеченные» (выбрать одну политику и не менять без причины) |

**Рекомендация для MVP:** шаг считается выполненным, когда все `checklist_items.done = true` *или* пользователь нажал **Сделано** (тогда неотмеченные авто-done / или блокер — лучше **блокер «отметьте все»** для shopping, чтобы не врать в прогрессе).

Логировать toggle каждого item в audit (`checklist_item_toggled`).

### Зачем

Один шаг «закупки» без чеклиста либо слишком крупный, либо распадается на 10 отдельных «Сегодня» — плохо для FCT и карбонары.

---

## Как это стыкуется с экранами

```text
Draft / Accept / Весь путь
  → groups как секции
  → steps
  → checklist внутри step (если есть)

Сегодня
  → один step
  → hero «Почему сейчас»
  → checklist UI если есть
  → Сделано / Пропустить
```

## Schema fragment (ориентир для LLM + validate)

```json
{
  "outcome": "…",
  "success_criteria": "…",
  "horizon": "…",
  "groups": [
    { "id": "shop", "title": "Покупки", "sort": 0 },
    { "id": "cook", "title": "Готовка", "sort": 1 }
  ],
  "actions": [
    {
      "id": "a1",
      "group_id": "shop",
      "title": "Купить продукты",
      "why": "Без этого нельзя начать соус",
      "detail": "Список ниже — минимум для классической карбонары",
      "estimate_min": 30,
      "day_offset": 0,
      "sort": 0,
      "checklist_items": [
        { "id": "c1", "title": "Яйца", "done": false, "sort": 0 },
        { "id": "c2", "title": "Гуанчиале", "done": false, "sort": 1 }
      ]
    }
  ]
}
```

Пустой `why` → reject.  
`group_id` без группы → reject или auto-create untitled (лучше reject).

---

## Не делаем (явный non-goal)

- Свободный UI-конструктор: произвольные блоки, вложенные экраны, LLM-сгенерированные виджеты  
- Более 2 уровней вложенности (group → step → checklist item — потолок)  
- Редактор структуры руками пользователя в MVP (только LLM + refine)

Клиент знает **три** презентационных типа: секция, шаг, чеклист-пункт.

---

## Приоритет внедрения

1. Плоский Path + «Сегодня» — день 1  
2. Groups в Path UI — сразу в schema create (дешево)  
3. Checklist items — сразу для shopping/prep шагов; без них готовка страдает  

Все три — **в scope MVP**, не «потом когда-нибудь».
