# 02 — Цели и гипотезы

## Зачем этот срез

Не проверить «умеет ли LLM строить планы» (это уже POC).

Проверить:

> Становится ли Facio вещью, которой **сами** готовы пользоваться на карбонаре и пути к 30 отжиманиям — с возвратом на следующий день и желанием нажать «следующий цикл»?

Внешний юзер-тест — **после** dogfood-бара, не до (см. [07](./07-testing-stance.md)).

---

## Ядро продукта (next)

```text
Intent
  → Slim start (быстро): смысл + вопросы (+ грубый outline)
  → Полный Path/Cycle + plugins доезжает на фоне
  → Правки на живом плане (batch clarify / repair) — без Draft→Accept-дубля
  → «Сегодня» = день/сессия с исполняемыми плагинами (timer | timeline | interval | counter)
  → Конец цикла → детерминированный CTA «следующий цикл»
       → summary результатов + batch уточнения → Cycle N+1
```

Устаревает: обязательный конвейер Draft studio → Accept (повтор карты) → live. См. [09](./09-continuity.md).

## Гипотезы

### H1 — Полный Path рано, не «на Accept»

Скрытие «настоящего» маршрута до Accept убивает «поняло + уже показывает как». Accept-дубль карты — тоже.

**Ожидание:** план виден и правится на одном экране; полный исполняемый слой может доезжать после slim, но не прячется «для интриги».

### H2 — Batch clarify

Один вопрос → пересбор → следующий вопрос ощущается как интервью.

**Ожидание:** 2–4 вопроса + комментарий за один submit; меньше раундов; Path visibly меняется.

### H3 — Narrative на плане

Без title/summary план = todo. С коротким смыслом в начале — «тренер объяснил».

**Ожидание:** qualitative dogfood — «понятно, к чему идём за цикл», не только список дней.

### H4 — Plugins = ценность wedge

Карбонара без оси времени / отжимания без Counter — списки, не продукт. Плоский TimerStack — база, не потолок.

**Ожидание:** на эталонах нужный clock-shape (timeline / interval / timer) + counters; ими пользуются в сессии. Slim create не откладывает смысл на 20с.

### H5 — Cycle + schedule

Плоская очередь не передаёт «день 2 — отдых».

**Ожидание:** Home показывает день цикла и kind; «Весь путь» — карта дней; продление создаёт Cycle N+1, а не бесконечный хвост actions.

### H6 — Детерминированное продление

CTA «следующий цикл» — кнопка продукта; модель может предложить **подпись**, не решение «есть ли кнопка».

**Ожидание:** после завершения (или частичного) цикла жест понятен без чата.

### H7 — Repair must (+ живой план)

Без «не могу / сдвинь» цикл умирает к дню 3. Draft→Accept-дубль мешает тому же классу правок на first-run.

**Ожидание:** repair/refine на одном живом плане; проект не бросают из-за одного пропуска.

### H8 — Общие примитивы, два эталона

Готовка и тренировки на одних plugins; качество гоняем на карбонаре и отжиманиях, не на «любой intent».

**Ожидание:** оба сценария проходимы end-to-end; прочий intent — best-effort, не блокер среза.

## Успех (качественно, до внешних юзеров)

- Автор/команда реально пользуются эталонами несколько дней
- First-run: быстрый slim-кадр + план без ощущения опросника и без дубля Accept
- «Сегодня» с timeline/interval/timer/counter ощущается нужнее, чем заметка
- Есть хотя бы один переход Cycle → Cycle N+1
- Repair спасает срыв, а не только «Пропустить»

## Провал

- Снова «красивый список» без runtime
- 20с пустоты до первого полезного кадра
- Обязательный Accept с повторной полной картой как главный loop
- Плагины невидимы на плане / только текст «через N мин»
- Продление через чат / свободный промпт
- Внешний тест POC и ложный no-go
- Repair отложен «на потом»
