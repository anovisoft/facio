# 08 — План реализации (этапы для субагентов)

Рабочий процесс:

```text
Шаг 0  — этот план → ты правишь / одобряешь
Шаг 1  — субагент на Срез 1 → ты правишь / одобряешь
Шаг 2  — субагент на Срез 2 → …
…
```

Правила для каждого среза:

- Один срез = одна передача субагенту с контекстом `docs/next` + DoD ниже.
- Не прыгать через срез без явного ок.
- После среза — короткий dogfood на уместном эталоне (см. ниже), не «всё зелёное в коде».
- Кодовых уточнений в этом файле нет: контракты и файлы решает исполнитель внутри среза, опираясь на [04](./04-model.md) и [05](./05-ux-flows.md).

Связанные документы: [01](./01-diagnosis.md) … [07](./07-testing-stance.md), эталоны [06](./06-reference-scenarios.md).

|------|-----|-------|----------------|

## Срез 1 — Narrative + полный план на draft + batch clarify

### Погружение

Сейчас draft показывает Path, но уточнения идут по одному вопросу, а Accept ощущается местом, где «настоящий» план наконец появляется. Пользователь не чувствует «уже ведём по полной карте» и устаёт от интервью.

Нужно: на draft сразу **заголовок + короткое описание в начале**, полный скелет пути (как сейчас умеем показывать, без урезания «для интриги»), все вопросы раунда на одном экране + поле «ещё важно», один жест «обновить путь».

### Входит

- Поля narrative плана: title, summary; описания групп где уместно; detail у шагов не терять
- Промпты/валидация так, чтобы эталоны стабильно получали title+summary
- UI draft: все clarify сразу + comment → один refine
- Accept остаётся контрактом, не первым показом карты
- Сохранить soft-start, назад/версии, словарь UI

### Не входит

- Cycle/days kind как first-class UI (это срез 2)
- Таймеры/каунтеры (срез 3)
- Repair / next cycle

### DoD

- [ ] На create эталона видны title и короткий summary в начале
- [ ] На draft видны все вопросы раунда; comment уходит вместе с ответами одним обновлением
- [ ] Нет обязательного «один chip → ждать LLM → следующий вопрос» как основного loop
- [ ] Accept не является первым экраном с полной картой
- [ ] Короткий прогон: карбонара и отжимания create→refine(batch)→accept без регресса чеклиста

### Контекст субагенту

Прочитать: README, 01, 02, 03 (first-run), 04 (§1–2, §6), 05 (first-run + draft layout), 06.  
Не трогать: cycle lifecycle, plugins кроме существующего checklist, repair, next cycle.

## Срез 2 — Cycle + schedule/дни + Home «день N»

### Погружение

Даже с красивым first-run Home всё ещё «следующий пункт списка». Для отжиманий критично: день 1 силовая, день 2 отдых — разные смыслы. Нужна граница **цикла** и **карта дней**, иначе позже не к чему привязать next cycle.

### Входит

- Cycle как единица проекта (horizon, индекс, статус)
- Дни: индекс + kind (`train` | `rest` | `cook_session` | `other`) + понятный «Сегодня»
- «Весь план» как карта дней цикла
- Defaults: короткий cycle для готовки; ~7 дней для отжиманий
- Home показывает «День N из M · kind», а не только голый next action

### Не входит

- Полноценные Timer/Counter (можно оставить слоты/пустые места под срез 3, но не обязателен runtime)
- Гибкий «N раз в неделю в любые дни»
- Next cycle CTA (срез 5)
- Сложный repair (срез 4) — достаточно не сломать существующий skip

### DoD

- [ ] Эталон отжиманий: на draft/accept/path видна неделя с разными kind
- [ ] Home: день rest визуально/смыслово отличается от train
- [ ] Карбонара: короткий cycle / cook_session не ломается
- [ ] Проект после Accept живёт в рамках текущего цикла

### Контекст субагенту

Прочитать: 03 (schedule/cycle), 04 (§3–4), 05 (Home + весь план), 06.  
Опереться на результат среза 1 (narrative + batch).  
Не строить продление цикла и плагины целиком.

## Срез 3 — Plugins: TimerStack + Counter

### Погружение

Без исполняемых узлов карбонара = рецепт-todo, отжимания = список подходов текстом. Ценность Facio здесь: таймеры с разными сигналами и каунтеры дозы. На create план уже выглядит как в использовании; до Accept контроли выключены.

### Входит

- TimerStack: несколько таймеров, фон, `nudge` vs `alert`
- Counter/Dose: target/current, удобное изменение (tap и/или swipe)
- Preview на draft/accept (disabled); live после Accept
- Checklist остаётся; LLM на эталонах обязан ставить нужные plugins уже на create
- «Сегодня» умеет вести сессию дня с этими плагинами

### Не входит

- Произвольные новые типы виджетов
- Богатый evidence (фото/видео)
- Next cycle
- Идеальная полировка анимаций — достаточно working runtime

### DoD

- [ ] Карбонара: на готовке есть таймеры; в live реально тикают/уведомляют по классам сигнала (хотя бы базово)
- [ ] Отжимания: каунтеры на подходах/повторах в live
- [ ] На draft те же плагины видны, но не стартуют
- [ ] Create эталонов стабильно кладёт plugins в план, не только текст

### Контекст субагенту

Прочитать: 03 (plugins), 04 (§5), 05 (Home plugins), 06.  
Опереться на срезы 1–2 (план + дни).  
Не делать repair/next cycle, кроме совместимости с текущим Сделано/Пропустить.

## Срез 3′ — Progressive create + clock UX (после dogfood 3)

### Погружение

Plugins на create есть, но: (1) ~20с пустоты до первого кадра; (2) плоский TimerStack плохо юзается на карбонаре; (3) Draft→Accept дублирует карту. Нужен быстрый slim-старт и семейство clock-shapes; Accept-конвейер схлопнуть к живому плану (частично здесь, добить в Срезе 4).

### Входит

- Slim фаза 1 = ветка + start surface
- Фаза 2 = Path **без** plugins + **plugin hints** на actions (фон; UI подмена)
- Фаза 3 = materialize plugins **после** «Начать сегодня» (маленькая schema; позже можно N×#3)
- Timeline / Interval / TimerStack / Counter в модели+UI (live после #3)
- Схлоп Accept → «Начать сегодня»
- Failed phase-2/3: не вечный спиннер; llm_calls с error не rollback’ать

### Не входит

- Полноценный Repair playbook (Срез 4)
- Next cycle (Срез 5)
- Chat-home
- Кнопка «Загрузить плагины» как главный CTA

### DoD

- [ ] Path-intent: полезный кадр раньше полного Path; план доезжает **без** grammar 400
- [ ] На плане видны hints tools, не обязателен полный disabled clock UI
- [ ] После Start: карбонара получает timeline (live); fitness — interval/counter где hint
- [ ] Нет обязательного Accept с дублем PathList
- [ ] Failed create path виден в llm_calls / UI не крутит спиннер вечно

### Контекст субагенту

Прочитать: 02, 03 (C′), 04 (clock family), 05, **09 решение B (3 фазы)**.  
Grammar: #2 без plugin objects; #3 отдельно; не dual-branch Path+instant.

## Срез 4 — Repair + физический день (на живом плане)

### Погружение

Multi-day без «не могу сегодня» умирает к дню 3. Skip недостаточен. Сейчас хуже: **физического дня нет** — закрыл день 1 → сразу день 2 (очередь actions). Repair без calendar unlock пустой. Поэтому в срезе: (1) physical-day gate, (2) Repair как мутация живого плана. Не строить поверх мёртвого Draft→Accept.

### Входит

**A. Физический день**
- Якорь цикла от `committed_at` (+ `first_step_when` today/tomorrow → сдвиг D0)
- `unlocked_day_index` от локальной даты пользователя; нельзя **выполнять** дни вперёд
- Catch-up: незакрытый прошлый день остаётся focus
- **Preview locked days:** будущие дни видны на карте / «Весь план» (и peek с Home); complete/skip/plugins disabled
- Home: execute только на focus ≤ unlocked; если сегодняшний слот закрыт раньше календаря — peek «завтра», не авто-день+1
- Карбонара horizon=1 — без регресса

**B. Repair**
- Жест с Home: не могу / сдвинуть / облегчить / заменить на rest
- Обновление текущего цикла согласованно с днями и «Сегодня» (с учётом unlock)
- Версионирование / audit в духе mvp
- Короткий user-visible итог «что сдвинули»

### Не входит

- Полноценный AI-coach чат
- Все playbooks из RFC
- Next cycle (но repair/unlock не должны ломать будущий цикл)
- Google Calendar sync / «N раз в любые дни недели»

### DoD

- [ ] Закрытие дня N не открывает **execute** дня N+1 до следующего calendar day
- [ ] Будущие дни видны (план / peek), но complete/skip/plugins недоступны
- [ ] На fitness-дне можно вызвать repair и получить новое осмысленное «Сегодня»
- [ ] Проект не «ломается» и не требует пересоздания с нуля
- [ ] Карбонара не регрессит (короткий cycle / horizon 1)
- [ ] Правка ощущается на одном плане, не «вернуться в draft → снова accept»

### Контекст субагенту

Прочитать: 02 (H7), 03 (schedule + repair), 04 (§4 physical day + §8), 05 (repair + живой план), 06, 09 (A + physical day).  
Опереться на 1–3 (+ 3′).

## Срез 4′ — Session Stage + Stepper (Home + prompts + schema)

### Погружение

Home сейчас — буклет: labels, why, detail, checklist, плагин снизу. Timeline/counter не ощущаются состоянием экрана. Силовая сессия ломается на «checklist подходов + один counter» и два action (max+volume). Нужны: (1) Session Stage UI, (2) stepper plugin, (3) промпты, чтобы LLM проектировал правильные объекты.

### Входит

**A. Model + prompts**
- `stepper` / `set_plan` на action: beats `measure|work|rest` (+ counter на work/measure, duration на rest)
- Hint `#2`: `"stepper"`; полные beats в `#3` (отдельный slim schema если grammar жмёт)
- Промпты create/refine/materialize: cook→timeline; силовая→один action+stepper; запрет checklist-подходов; merge max+volume
- Few-shot отжимания: неделя 1 с stepper на train-дне

**B. Home UI — Session Stage**
- Stage ~2/3: timeline или текущий stepper beat (+ compact при скролле)
- Support: короткий title / «Сейчас»
- **Бургер справа сверху** → Весь план (Path); убрать/понизить дубль CTA «Весь план» в теле
- Rest day — спокойный вариант stage
- Done / Skip / Repair — вторичный chrome

**C. Path preview**
- Locked days как сейчас; hint chips включают stepper

### Не входит

- Next cycle (Срез 5)
- Полный redesign Draft
- Google Calendar

### DoD

- [ ] Силовая: один session action со stepper (не checklist подходов + 1 counter)
- [ ] Home: stage доминирует; бургер открывает весь план
- [ ] Карбонара: timeline как stage (не буклет)
- [ ] Промпты/few-shot отражают концепт; #3 materialize stepper без grammar 400
- [ ] Существующие carbonara/fitness тесты зелёные или обновлены

### Контекст субагенту

Прочитать: 03 (plugins), 04 (§5 stepper + clock), 05 (Session Stage + бургер), 06, 09 (§F).  
Опереться на 3′ + 4.

## Срез 5 — Next cycle

### Погружение

Закрытие петли «персональный тренер»: неделя пройдена (хотя бы частично) → детерминированная кнопка → следующая неделя на базе фактов + уточнения. Без чата как главного жеста.

### Входит

- Граница завершения цикла (полный / «завершить с частичным прогрессом»)
- Structured итог цикла (`cycle_result`)
- CTA **«Следующий цикл»** (детерминировано); optional `continue_label` от модели
- Построение цикла N+1 из prior + results + batch clarify при необходимости
- История/индекс циклов внутри проекта
- Новый `cycle_anchor_date` на N+1; plugins materialize как на первом start

### Решения при одобрении (2026-08-01)

| Вопрос | Решение |
|--------|---------|
| Частичный complete | Кнопка «Завершить цикл» + итог с partial notes |
| Clarify перед N+1 | Как refine: 0–few вопросов + «Ещё важно»; не обязательный отдельный Accept |
| UI итога | Блок / sheet на Home (живой план), не Draft→Accept-дубль |
| Карбонара (`horizon_days=1`) | CTA **«Повторить»** (явный repeat), не скрывать и не noop-тихо |

### Не входит

- Marketplace программ / монетизация
- Свободный чат «придумай что дальше»
- Domain-aware Repair, Home polish (backlog [09](./09-continuity.md)); cook prep≠timeline — **в коде / ждёт dogfood**

### DoD

- [x] Отжимания: после недели виден CTA; по нажатию появляется цикл 2, осмысленно связанный с результатами — **в коде / ждёт dogfood**
- [x] Жест продления не требует чата — **в коде**
- [x] Цикл 1 остаётся в истории/доступен для понимания «что было» — **в коде** (`cycles_history`)
- [x] Карбонара: CTA «Повторить» после завершения вечера; не ломает horizon=1 — **в коде / ждёт dogfood**
- [x] Physical day на N+1: новый якорь; locked preview как сейчас — **в коде**
- [x] Тесты зелёные / обновлены — **в коде** (`tests/test_next_cycle.py`)
