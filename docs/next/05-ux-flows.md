# 05 — UX и потоки

Главный принцип из mvp/ сохраняется:

> Пользователь не должен думать «что дальше?».  
> Экран отвечает: какой следующий шаг / день сейчас — и почему.

Дополнение next:

> И видит **тот же** исполняемый план — Plan as Runtime Artifact.

**После dogfood Среза 3 (зафиксировано):** цикл Draft → Accept → live **устарел**. Accept дублирует карту. Цель — один живой план + явные мутации (refine / repair / next cycle), не chat-home. Детали — [09](./09-continuity.md).

---

## Словарь

| В продукте | Смысл |
|------------|--------|
| План / путь | Cycle + schedule + steps + plugins |
| Сегодня | Текущий день цикла / сессия дня |
| Сделано | Закрытие шага или дня (политика по типу) |
| Пропустить / Не сейчас | Skip + лог |
| Начать / Сессия | Явный старт исполнения дня/шага (вместо тяжёлого Accept-дубля) |
| Уточнить / Поправить | Refine или Repair на **том же** плане |
| Следующий цикл | Детерминированный CTA |
| Почему сейчас | Hero why текущего шага |

Устаревает как отдельный обязательный экран: **Принять путь** с повторным полным PathList.

Нет: Chat-home, «Done/Action» в copy, продление «через диалог с ИИ» как единственный жест.

## First-run — направление (progressive + живой план)

```text
Intent
  → Slim start (быстро):
       kind = path | instant_answer
       если path: paraphrase + title/summary-черновик + batch questions
                  (+ опционально грубый outline дней, без plugins)
  → Поверхность плана сразу (можно отвечать на вопросы)
  → Фон: полный Path + plugins → UI подменяется, когда готов
  → Уточнения / правки на том же экране (batch + comment → refine)
  → «Начать сегодня» / старт сессии (лёгкий контракт при необходимости)
  → Home / сессия с live plugins
  → Repair и refine — те же жесты правки живого плана
```

**Legacy (ещё в коде Срезов 1–3, не целевой канон):** Draft studio → отдельный Accept с полным дублем карты → live.

**Не делаем:** прятать смысл/каркас до первого кадра (пустота 20с).  
**Не делаем:** прятать полный исполняемый слой «для интриги» до Accept — но полный Path **может доезжать** после slim.  
**Не делаем:** один clarify → полный LLM roundtrip → следующий clarify как основной loop.  
**Не делаем:** chat как главная поверхность.

## Draft studio (layout) — канон после dogfood 3′

Живой план-экран (не отдельный Accept). Конфликт clarify vs длинный PathList решён так:

```text
Ок — ведём к: {paraphrase}

{title}
{summary}

Краткий план                          ← compact outline (дни / короткие шаги)
  · День 1 · …
  · День 2 · …
  [ Смотреть весь план ]              ← полный PathList по запросу

Чтобы путь был точнее:                ← если questions[] не пуст
1. {q}  [chips]
2. {q}  [chips]

Ещё важно:                            ← ВСЕГДА (и при 0 вопросов)
[ comment ]

──────── sticky footer ────────
[ Назад версии ]  [ Обновить путь ]
[ Сохранить и приступить ]            ← primary → Home + plugins #3
[ Сохранить ]                         ← secondary → Projects (active)
```

Пока path #2 грузится: outline из gate / «собираю…»; вопросы и comment уже доступны.  
Ответы clarify **не сбрасывать** при приходе path (только при смене набора question id).

**Не делаем:** табы Вопросы|План; сегодня/завтра switcher; полный PathList в потоке во время clarify (кнопка уезжает).

Детали решений: [09 §D](./09-continuity.md).

## Accept (layout) — legacy / схлопнут

Отдельный экран с полным PathList убран. Commit с экрана плана:

- «Сохранить и приступить» → Home
- «Сохранить» → список проектов

`first_step_when` на API остаётся (default today); UI switcher не показываем.

## Project Home — Session Stage (канон)

Отказ от «буклета» (пачка labels + длинный текст + плагин снизу).  
**Исполняемый shape = состояние экрана.** Текст — поддержка.

### Chrome

```text
[ back / title ]              [ ☰ бургер ]
```

- **Бургер справа сверху** → открывает **Весь план** (PathScreen / sheet). Не дублировать огромной кнопкой «Весь план» в теле, если бургер есть.
- Repair / Сделано — вторичный chrome внизу или у края stage, не конкурируют с героем.

### Layout (первый экран)

```text
┌─────────────────────────────┐
│  SESSION STAGE  (~2/3)      │  ← timeline | stepper | interval
│  единственный визуальный    │
│  фокус «где я сейчас»       │
├─────────────────────────────┤
│  Support: title · «Сейчас»  │  ← 1–2 строки
│  (detail / why — скроллом)  │
└─────────────────────────────┘
   скролл вниз → stage сжимается
   в compact sticky bar (всегда виден)
```

| Shape | Stage |
|-------|--------|
| timeline (готовка) | Большая ось + now-marker; compact при скролле |
| stepper (зал) | Текущий beat (counter или rest-timer) + тонкая лента битов |
| interval | Текущий сегмент + pause |
| rest day | Спокойный stage без гигантского таймера |
| нет session plugin | Короткий support + checklist/простые controls (не буклет) |

### Анти-паттерны

- Uppercase-лейблы равного веса («СЕГОДНЯ», «ПОЧЕМУ», «ПОВТОРЫ»)
- Checklist «Подход 1/2/3» рядом с одним counter
- Два action (max + volume) как два абзаца одной силовой — merge в один stepper
- Плагин спрятан под стеной detail

### Весь план (из бургера)

- Карта дней cycle с kind; locked days видны, execute disabled
- Внутри — шаги + plugin hints / stage preview
- Groups как секции где уместно

## Repair

```text
Не могу сегодня
  → варианты: сдвинуть день / облегчить / заменить на rest
  → подтверждение короткого diff
  → новый «Сегодня» (с учётом physical unlock)
```

Минимум must; без этого multi-day dogfood ломается.

## Физический день (Home)

```text
unlocked_day_index от local_today − cycle_anchor
focus = earliest pending ≤ unlocked  → execute (Сделано / plugins)
дни > unlocked → видны на «Весь план» и peek, controls disabled
закрыл день рано → peek завтрашнего, не авто-execute день+1
```

См. [04 §4](./04-model.md).

## Конец цикла → следующий

```text
Цикл N завершён (или «завершить цикл» при частичном прогрессе)

Итог: сделано X, пропущено Y, …
[структурированный summary]

[ Следующий цикл ]     ← детерминировано
  subtitle/hint?: «Продолжить тренировки»  ← optional copy от модели

→ короткий batch clarify под N+1 (если нужно)
→ новый cycle на базе prior + results
→ новый cycle на базе prior + results (на том же живом плане; минимум трения, без дубля Accept)
```

Продукт: жест продления **очевиден и не chat**.

## Чего не должно быть

- Accept как «впервые показали маршрут» **или** как обязательный дубль полной карты
- Долгая пустота до первого полезного кадра (slim start обязателен по направлению)
- Clarify по одному с обязательным ожиданием после каждого chip
- Плагины только после commit, невидимые на плане
- Продление только через свободный промпт
- Home = чат (под капотом операции ок; поверхность — план)
- Одинаковый UI для train и rest
- Только плоский TimerStack там, где нужна ось сессии (карбонара) или interval+pause (тренировка)
