# 05 — UX и потоки

Главный принцип из mvp/ сохраняется:

> Пользователь не должен думать «что дальше?».  
> Экран отвечает: какой следующий шаг / день сейчас — и почему.

Дополнение next:

> И видит **тот же** исполняемый план, что принял — сначала preview, потом live.

---

## Словарь

| В продукте | Смысл |
|------------|--------|
| План / путь | Cycle + schedule + steps + plugins |
| Сегодня | Текущий день цикла / сессия дня |
| Сделано | Закрытие шага или дня (политика по типу) |
| Пропустить / Не сейчас | Skip + лог |
| Принять путь | Hard commit → live |
| Следующий цикл | Детерминированный CTA |
| Почему сейчас | Hero why текущего шага |

Нет: Chat-home, «Done/Action» в copy, продление «через диалог с ИИ» как единственный жест.

---

## First-run (канон next)

```text
Intent
  → gate (path | instant_answer)  # как mvp
  → Soft-start (paraphrase)
  → Draft studio:
       title + summary
       полная карта cycle/days + steps + plugins (preview / disabled)
       batch questions (все) + comment field
       [Обновить путь] → один refine-pass
       при необходимости — ещё один короткий batch (редко)
  → Accept:
       контракт (успех, горизонт, нагрузка, когда старт)
       тот же план (уже знакомый)
       [Принять путь]
  → Project Home (live)
```

**Не делаем:** прятать полный маршрут до Accept.  
**Не делаем:** один clarify → полный LLM roundtrip → следующий clarify как основной loop.

---

## Draft studio (layout)

```text
Ок — ведём к: {paraphrase}

{title}
{summary}

План на цикл ({horizon_days} дн.)
─────────────────────────────
День 1 · train
  1. … [counter preview]
  2. …
День 2 · rest
  …
День 3 · …
[ плагины видны, контроли выключены ]

Чтобы путь был точнее — ответь сразу:
1. {q}  [chips]
2. {q}  [chips]
3. {q}  [chips]

Ещё важно (необязательно):
[ comment ]

[ Назад ]  [ Обновить путь ]

[ К принятию ]
```

---

## Accept (layout)

```text
{title}
Успех: {success_criteria}
Горизонт / нагрузка: {horizon}

(план уже виден — можно кратко свернуть/развернуть)

Когда первый день: [сегодня] [завтра] …

[ Принять путь ]   [ Ещё уточнить → draft ]
```

---

## Project Home — день цикла

```text
{title short}
День {n} из {horizon} · {kind label}

Сегодня
────────
{day.title / session}
~estimate

Почему сейчас
─────────────
{why текущего фокус-шага}

[ plugins live: timers / counters / checklist ]

[ Сделано ]  [ Пропустить ]  [ Не могу → repair ]

[ Весь план ]  [ История ]
```

Разный kind → разный акцент UI (rest не выглядит как силовая).

Сессия дня может содержать несколько plugin-steps; «Сегодня» ведёт по сессии, не обязательно одним тапом на весь день.

---

## Весь план

- Карта дней cycle с kind
- Внутри — шаги и preview/состояние plugins
- Groups как секции, если используются параллельно с days

---

## Repair

```text
Не могу сегодня
  → варианты: сдвинуть день / облегчить / заменить на rest
  → подтверждение короткого diff
  → новый «Сегодня»
```

Минимум must; без этого multi-day dogfood ломается.

---

## Конец цикла → следующий

```text
Цикл N завершён (или «завершить цикл» при частичном прогрессе)

Итог: сделано X, пропущено Y, …
[структурированный summary]

[ Следующий цикл ]     ← детерминировано
  subtitle/hint?: «Продолжить тренировки»  ← optional copy от модели

→ короткий batch clarify под N+1 (если нужно)
→ новый cycle на базе prior + results
→ снова preview → Accept/авто-activate (решить на реализации; предпочтение — меньше трения)
```

Политика auto-activate vs повторный Accept — open detail; продукт: жест продления **очевиден и не chat**.

---

## Multi-project

Как mvp: N active. Новый intent не закрывает другие.  
Cycle — per project.

---

## Чего не должно быть

- Accept как «впервые показали маршрут»
- Clarify по одному с обязательным ожиданием после каждого chip
- Плагины только после commit, невидимые на draft
- Продление только через свободный промпт
- Home = чат
- Одинаковый UI для train и rest
